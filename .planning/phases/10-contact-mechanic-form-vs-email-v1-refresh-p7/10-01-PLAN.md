<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Formspree | Form data leaves the static site to a third-party (Formspree) over HTTPS. Static site has no server code. |
| Formspree response → DOM | The fetch JSON response and status messages are written into the `#contact-status` aria-live region. |
| visitor input → DOM | User-typed name/email/message could theoretically be echoed back into the page. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Tampering (DOM XSS) | `#contact-status` rendering in `initContactForm` | mitigate | Render ALL status messages via `textContent` only; never `innerHTML`. Never echo user-submitted field values or raw Formspree JSON strings into the DOM — static strings only. (HIGH if violated; blocking.) |
| T-10-02 | Spoofing / spam bots | form submit endpoint | mitigate | Hidden `_gotcha` honeypot (Formspree convention) + client-side honeypot guard + Formspree built-in spam filter (D-06). No captcha (accepted tradeoff). |
| T-10-03 | Information disclosure | error/fallback status messages | mitigate | No email address in any status string (D-02). Generic retry copy only. Prevents harvesting + honours form-only decision. |
| T-10-04 | Information disclosure | data sent to Formspree (third-party) | accept | V1 accepted: free-tier Formspree is the chosen processor (D-03/D-08, Kris's account). Data-use note (D-07) discloses single purpose to the user. No PII beyond name/email/message; HTTPS in transit. |
| T-10-05 | Repudiation / DoS | unauthenticated public form | accept | Low-value target; Formspree rate-limits the free tier; honeypot reduces automated abuse. No additional control for V1. |
| T-10-SC | Tampering (supply chain) | npm/pip/cargo installs | accept | No new runtime packages installed (vanilla JS, no SDK — D-03). Playwright (Plan 02) is pre-existing dev-only tooling, gitignored, not shipped. No package-install task in this phase. |
</threat_model>
