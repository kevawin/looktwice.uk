## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| source config → generated SVG string | `CUTOUT_CONFIGS` + `SHAPE_PRESETS` + manifest values are interpolated into an SVG string written to dist/index.html |
| manifest (buildImages output) → `<image href>` | Image path comes from the build pipeline, not external/user data |

This is a static marketing site with build-time codegen and no server-side runtime. No auth, no runtime user input in this module. The only runtime input on the site is the Formspree contact form, which this phase does not touch.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Tampering | SVG string interpolation in buildSvgString | mitigate | All interpolated values (image href, viewBox, shape coords, alt) originate from controlled build inputs (`manifest` from buildImages, hardcoded CUTOUT_CONFIGS), never external/network data. No untrusted string reaches the SVG. Document this invariant in a code comment. |
| T-11-02 | Information Disclosure | manifest href selection | accept | Manifest paths are public asset URLs by design (the image is served publicly). No secret is exposed. |

| T-11-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages this phase (RESEARCH Package Legitimacy Audit: none). buildCutout.js uses only Node built-ins (fs, path). No install task, no legitimacy checkpoint required. |
