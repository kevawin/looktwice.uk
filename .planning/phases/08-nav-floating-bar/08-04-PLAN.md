<objective>
Close the two BLOCKER accessibility gaps verification found in Phase 08 (08-VERIFICATION.md, CR-01 and CR-02). Both stem from the same root cause: the floating bar's hidden state is decided in two code paths (the scroll-gate `onScroll` and the `#contact` IntersectionObserver) that can disagree, and neither path removes the bar's children from the tab order when the bar is invisible.

Fix CR-01 (WCAG 4.1.2): when the bar is hidden — pre-visible OR suppressed — its CTA anchor, burger button, and pills must leave the tab order. Add the `inert` attribute on the bar root, co-located with every `aria-hidden` toggle, in BOTH paths. Under reduced-motion the hidden bar is `opacity:0` in normal flow (no translate), so without `inert` the controls sit focusable on top of page content — `inert` is the fix that works in both motion modes.

Fix CR-02 (suppression desync + focus trap): the IntersectionObserver currently only toggles the `floating-bar--suppressed` class. Make it also set `aria-hidden="true"` (today it stays the stale `"false"` set when the bar became visible) and set `inert`, and call `closeMenu()` when the burger is open so scrolling #contact into view does not trap focus on an invisible pill.

Per the verifier's recommended approach, centralise the hidden-vs-visible decision in ONE function (`setBarHidden(hidden)`) that toggles `aria-hidden`, `inert`, and `floating-bar--visible` together, then call it from both paths. This guarantees the two paths cannot diverge.

Purpose: SC-6 (D-15/D-16) requires correct keyboard/focus management; CR-01 and CR-02 are direct failures of that contract. Re-satisfy REFRESH-P2-CONTACT-SUPPRESS and REFRESH-P2-A11Y-FOCUS (both left PARTIAL by verification).
Output: a corrected js/main.js with a centralised state function and a closing-on-suppress observer, plus new Playwright assertions that actually catch both bug conditions (the existing suite passes WITHOUT catching them).
</objective>
