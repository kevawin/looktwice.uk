# Phase 2 — UI Design Contract

> Visual and interaction contract for the Hero (`#hero`) and Situation (`#situation`) sections of looktwice.uk. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Phase 2 only fills two empty section anchors. Nav, overlay, footer, and the four other sections are out of scope. Token surface, font loader, base reset, and reduced-motion guard already ship from Phase 1 — do not redeclare.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — vanilla HTML/CSS/JS, no framework, no build step (CLAUDE.md tech stack) |
| Preset | not applicable |
| Component library | none — bespoke component classes in `css/components.css`, BEM-ish naming (`.hero`, `.hero__cutout--main`, `.situation__block`) |
| Icon library | none — no icons in Phase 2 (SITU-02 explicitly bans icons; hero has none) |
| Font | Epilogue (self-hosted woff2, weights 400 + 700, `font-display: swap`) — already loaded in `css/base.css` |

**Source of truth:** `css/tokens.css` (Phase 1) declares every colour, scale, radius, shadow, and transition. Phase 2 consumes via `var(--token-name)` only — never hard-codes.

## Spacing Scale

Spacing is locked by `css/tokens.css` (DESIGN-TOKENS.md). Phase 2 reuses the existing token scale unchanged.

| Token | Value | Phase 2 Usage |
|-------|-------|---------------|
| `--space-xs` | 8px | Stagger between number label and title within a situation block; gap inside button text/icon if needed |
| `--space-sm` | 16px | Vertical rhythm inside the hero text group (subhead → buttons), vertical gap inside a situation block |
| `--space-md` | 32px | Mobile gap between situation items (SITU-04); gap between hero text group and CTA row on mobile |
| `--space-lg` | 64px | Desktop column gap in the situation grid (SITU-03); gap between hero text column and cutout column on desktop |
| `--space-xl` | 96px | Reserved — Phase 5 collapses `--space-section` to this on mobile (RESP-02). Phase 2 uses on mobile situation top/bottom padding. |
| `--space-section` | 120px | Vertical padding of the situation section, top and bottom (SITU-01). |

Exceptions:
- Hero vertical padding is **not** `--space-section`. Hero is `min-height: 90vh` (HERO-01), with internal padding `--space-lg` top + `--space-lg` bottom on desktop, `--space-md` on mobile, plus enough to clear the sticky nav. The 90vh full-bleed surface drives the rhythm, not section spacing.
- Button padding is fixed at `14px 32px` (DESIGN-TOKENS.md Buttons spec). 14 is not a multiple of 8 but is locked by the design system; treat as token.
- Chip padding is fixed at `5px 14px` (DESIGN-TOKENS.md Chips spec). Same exception, locked.

## Typography

Type scale is locked by `css/tokens.css`. Phase 2 reuses; no new sizes, no new weights. Two weights only: 400 and 700. Never 500.

| Role | Size token | Size value | Weight | Line height | Letter spacing | Phase 2 Usage |
|------|-----------|-----------|--------|-------------|----------------|---------------|
| Display | `--text-display` | clamp(3rem, 7vw, 5.5rem) | 700 | `--lh-display` (1) | `--ls-display` (-0.02em) | Hero headline only — "Your brand makes a promise. But is your experience breaking it?" |
| Headline | `--text-headline` | clamp(1.75rem, 3.5vw, 2.75rem) | 700 | `--lh-headline` (1.1) | `--ls-headline` (-0.01em) | Situation section headline — "Sound familiar?" |
| Title | `--text-title` | clamp(1.25rem, 2vw, 1.5rem) | 700 | `--lh-title` (1.2) | normal | Situation block titles (the bold line under the 01–05 number on each block) |
| Body | `--text-body` | clamp(1rem, 1.5vw, 1.1rem) | 400 | `--lh-body` (1.7) | normal | Hero subhead, situation block body sentences |
| Label | `--text-label` | 0.8rem | 400 (chip) / 700 (button) | `--lh-label` (1.4) | `--ls-label` (0.1em) | "THE SITUATION" chip; situation block numbers (01–05); button labels (700) |

Rules:
- Hero headline ships as **two display lines**, line break between sentences (D-01). Use `<br>` inside the `<h1>` rather than two paragraphs.
- Hero subhead is **two short sentences as one beat**, no line break, no em-dash (D-02). Original em-dash from CONTENT-DRAFT is split into a period.
- Hero subhead uses `color: var(--color-true-white)` with `opacity: 0.85` (HERO-02). Do not introduce a new colour token for "white at 85%".
- Situation block numbers 01–05 use Label typography in `--color-hot-pink`. Numbers are uppercase by Label rule.
- Situation body copy is capped at `--measure` (65ch) per SITU-02.
- Italic is not used in Phase 2.
- Em-dashes are banned in copy (CLAUDE.md, DESIGN-TOKENS.md). All Phase 2 copy strings have already been verified em-dash-free in CONTEXT (D-02 fix).

## Color

Phase 2 paints two surfaces only: Hot Pink (`#hero`) and Linen (`#situation`). The 60/30/10 framing maps to Look Twice's "one accent per section" rule rather than a generic dashboard palette.

| Role | Token | Value (OKLCH) | Phase 2 Usage |
|------|-------|---------------|---------------|
| Dominant — Linen | `--color-linen` | oklch(97% 0.01 80) | Body default surface; situation section background; hero ghost button hover fill; primary button text colour |
| Dominant — Hot Pink (hero only) | `--color-hot-pink` | oklch(52% 0.28 0) | Hero full-bleed surface (HERO-01); situation block numbers 01–05 (Label typography); primary button hover fill on hero (HERO-04) |
| Secondary — Midnight | `--color-midnight` | oklch(24% 0.04 275) | "THE SITUATION" chip fill; situation section headline + block titles + body text; primary button fill (default state, HERO-04) |
| Accent — White | `--color-true-white` | oklch(100% 0 0) | Hero headline + subhead text; "THE SITUATION" chip text; primary button text on hover (against Hot Pink); ghost button border + text |
| Destructive | not used | — | No destructive actions in Phase 2 |

Accent reserved for (the 10% rule, expressed as Look Twice's One-Surface Rule):
- **Hot Pink** appears in Phase 2 in exactly three places: the hero full-bleed background, the situation block numbers (01, 02, 03, 04, 05), and the primary CTA button hover state on the hero. Nowhere else.
- **Brand gradient** is **not** used in Phase 2. Reserved for the floating sticky tab in Phase 4 (CLAUDE.md gradient discipline; DESIGN-TOKENS.md One Gradient Rule).
- **Cool accents** (Rich Purple, Cool Indigo) are not used in Phase 2 (DESIGN-TOKENS.md Cool Accent Rule). They appear as gradient stops only, never on hero or situation.
- **Mid-tone greys** are banned (CLAUDE.md, DESIGN-TOKENS.md). White-at-85%-opacity for the hero subhead is opacity on White, not a grey token.

Contrast notes (verified in Phase 5 / A11Y-03; reflected in implementation now):
- Hero headline = White 700 on Hot Pink → use 700 weight as locked above. 400 fails AA on Hot Pink and is not used at Display size.
- Hero subhead = White 400 at 85% opacity on Hot Pink → borderline; checker should flag, but mitigated by short subhead length and Body size (≥16px). If Lighthouse fails in Phase 5, increase opacity to 100% before changing weight — never introduce a new colour token.
- Situation body = Midnight 400 on Linen → passes AAA, no concern.
- Situation chip = Linen on Midnight → passes AAA.

## Layout

### Hero (`#hero`)

**Desktop (>1024px):**
- Full-bleed Hot Pink, `min-height: 90vh`.
- Two-column grid inside `.hero__inner`. Text column ~55%, cutout column ~45%. CSS Grid `grid-template-columns: minmax(0, 55fr) minmax(0, 45fr)`, gap `--space-lg`.
- Vertical centring of text column. Cutout column: main cutout positioned right-dominant or centre-right, supporting cutout offset asymmetrically (planner picks exact x/y; brief is "asymmetric tension", not symmetrical).
- Text never overlaps photography (HERO-03, D-11).

**Tablet (640–1024px):**
- Same two-column structure but column ratio relaxes (planner judges; recommend ~50/50 with cutout slightly smaller).
- If content overflows or collisions occur, drop to mobile layout at the planner-chosen breakpoint (recommend 768px).

**Mobile (<640px or <768px per planner):**
- Single column, stacked: headline → subhead → buttons → cutout composition.
- Cutout scales to ~85% section width (HERO-05).
- Buttons stack vertically, full-width or auto-width (planner judges; recommend full-width up to a max for tap-target generosity).

### Situation (`#situation`)

**Desktop (>1024px):**
- Linen full-width.
- `--space-section` (120px) top + bottom padding.
- Inside `.situation__inner`: chip + headline stack at top.
- `.situation__grid` is a CSS Grid with two columns, gap `--space-lg` (64px).
- Items 01, 02, 03 in column 1. Items 04, 05 in column 2, with column 2 offset down by approximately one item height to create the staggered rhythm (SITU-03). Implement via `padding-top` on column 2 wrapper, or via `grid-row` placement, or via a leading empty grid cell — planner picks the cleanest approach.

**Tablet (640–1024px):**
- Same two-column staggered grid. Column gap may relax to `--space-md`.

**Mobile (<640px):**
- Single column, full width.
- `--space-md` (32px) between items (SITU-04).
- Section padding collapses to `--space-xl` top + bottom (forward-compatible with RESP-02 collapse rule; Phase 2 may ship desktop value only and Phase 5 will collapse — planner picks).

## Interaction & Motion

### Reveal animation contract

| Property | Value |
|----------|-------|
| Trigger | `IntersectionObserver`, threshold `0.2` (D-13) |
| Observed elements | All elements with class `.reveal` (single generic observer per D-14) |
| Initial state | `opacity: 0; transform: translateY(16px);` (declared in `css/animations.css` Phase 1 stub) |
| Final state | `opacity: 1; transform: translateY(0);` via `.reveal.visible` |
| Transition | `--transition-reveal` (opacity + transform 400ms cubic-bezier(0.16, 1, 0.3, 1), declared in tokens) |
| One-shot | Yes — `observer.unobserve(el)` after first reveal (D-15) |
| Reduced motion | Opacity-only fade, no transform; `transition: opacity 400ms ease-out` (D-17, already in `css/animations.css` reduced-motion guard) |

### Phase 2 elements that carry `.reveal`

Hero never reveals on scroll (D-16, HERO-06). Hero markup carries no `.reveal` class.

| Element | `.reveal` index | Stagger delay |
|---------|----------------|---------------|
| `.situation__chip` | 0 | 0ms |
| `.situation__headline` | 0 | 0ms (reveals together with chip — same conceptual "header" group) |
| `.situation__block` (item 01) | 1 | 80ms |
| `.situation__block` (item 02) | 2 | 160ms |
| `.situation__block` (item 03) | 3 | 240ms |
| `.situation__block` (item 04) | 4 | 320ms |
| `.situation__block` (item 05) | 5 | 400ms |

Stagger implementation pattern (planner picks one, both fit D-14):

**Option A — `data-reveal-index` consumed by JS:**
```html
<li class="situation__block reveal" data-reveal-index="1">…</li>
```
```js
document.querySelectorAll('.reveal').forEach((el) => {
  const i = parseInt(el.dataset.revealIndex || '0', 10);
  el.style.transitionDelay = `${i * 80}ms`;
});
```

**Option B — `--stagger-delay` CSS custom property set inline:**
```html
<li class="situation__block reveal" style="--stagger-delay: 80ms;">…</li>
```
```css
.reveal { transition-delay: var(--stagger-delay, 0ms); }
```

Recommendation: Option A. Pure data attribute, no inline style, JS owns the timing math. Planner confirms.

Note: chip + headline both at index 0 means they reveal simultaneously. Phase 2 treats the chip+headline as a single "header" beat per HOMEPAGE-SPEC §Section 3 ("Section headline + label chip fade in first").

### Hero motion

- No reveal on scroll (D-16, HERO-06).
- Visible immediately on load. No `.reveal` class on any hero element.
- Buttons hover transition: 180ms ease-out on background-color + color (`--transition-button`). No transform, no shadow change.
- Cutouts: static. No parallax, no Ken Burns, no ambient animation (HOMEPAGE-SPEC: "No parallax. No decorative animation. No ambient motion.")

### Hover & focus states

| Element | Default | Hover | Focus-visible |
|---------|---------|-------|---------------|
| `.btn--primary` | Midnight fill, Linen text | Hot Pink fill, White text, 180ms | 2px Hot Pink outline, 3px offset (inherits global `:focus-visible` from `css/base.css`) |
| `.btn--ghost-on-dark` | Transparent fill, 1.5px White border, White text | White fill, Midnight text, 180ms | Same global focus ring; verify the Hot Pink outline reads against Hot Pink surface — if it disappears, override to White outline on this button class only |
| Cutout images | static, `filter: grayscale(100%)` | no hover state — images are not interactive | not focusable |

Focus-ring exception note: Hot Pink outline on Hot Pink surface = no contrast. The hero ghost button must override `:focus-visible` to `outline: 2px solid var(--color-true-white); outline-offset: 3px;`. Planner implements; checker verifies.

## Accessibility Hooks (Phase 2 ships, Phase 5 audits)

- One H1 per page = the hero headline. Situation section headline is H2. Each situation block title is H3 (A11Y-01).
- Both cutouts have descriptive alt text per CONTENT-DRAFT.md guidance (A11Y-02). Never `alt=""` on the live images. Fallback Midnight blocks have no alt (decorative).
- All five situation blocks live inside an `<ol role="list">` so screen readers announce them as an ordered list of 5. Numbers in the visible UI are content (`<span>` not generated) so they read aloud.
- `prefers-reduced-motion: reduce` already collapses reveals to opacity-only fade via the existing `css/animations.css` guard (D-17).
- Both CTAs are `<a>` elements with `href` attributes (not `<button>`), reachable by keyboard in tab order matching visual order (A11Y-04 forward-compatible).
- Global `:focus-visible` ring from `css/base.css` (2px Hot Pink, 3px offset) applies to both CTAs. Override required on the ghost button only (focus-ring colour swap to White against the Hot Pink surface — see Hover & focus table above).
